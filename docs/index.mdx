A cell describes what plays: settings, named parts and `play` statements. The interpreter evaluates the cell and renders each `play` to audio, with a grid of every hit and note.

<Cell>

```composer-nb
time 7 over 8
tempo 110
octave 2
guitar.electric muted

pattern groove = {
  kick: x--x---
  snare.rim: ----x--
  ride.bell: x--
  guitar.electric: D---E D-D--
}

play 3 bars {
  {
    snare.rim: ^-
  } {
    bar 1 crash: 1
    groove
  }
}
```

</Cell>

This is *What Happens Now?* by Porcupine Tree. The `play` holds two blocks joined by `} {`, so they play in [sequence](/language/overview#blocks): an accented rim as a pickup, then the groove with a crash in its first bar. Each line of `groove` repeats at its own length: 7 steps for the kick and rim, 3 for the ride bell, 10 for the guitar. They only meet again after 15 bars, and `play 3 bars` stops it after three.

## Why instructions

- **You state the rules, the interpreter writes the bars.** Two lines of different lengths make a polyrhythm that would take pages to write out, and you hear where they meet without working it out.
- **Every edit is a new take.** Change a step, a length or the time signature, evaluate, and listen.
- **Parts are values.** A groove is named once and reused under every section, a song is a sequence of names, and a cell is source you can diff, version and generate from Python.

## Run it

- **Playground.** Open [composer-nb.vercel.app](https://composer-nb.vercel.app), select a cell and press Shift+Enter. Nothing to install.
- **Jupyter.** `pip install composer-nb`. See [Jupyter](/jupyter).

Every example on this site is a live cell: edit it and press Run.
