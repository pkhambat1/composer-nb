## Cells

A cell is a program. The interpreter evaluates its statements top to bottom, one per line outside braces, and each `play` renders one output. Nothing else makes sound. `//` starts a comment, and a line that starts with `|` continues the line above it, at a bar line.

Inside braces, commas separate entries; newlines are layout. A final comma before `}` is allowed: `pattern beat = { kick: x---, hat: x-, }`. Semicolons are errors. Commas in function arguments and `with` settings belong to those expressions. Note words use spaces and step repeats: `piano: notes 1 7*- 3 7*-,`.

| Statement | Example | Allowed |
| --- | --- | --- |
| Setting | `set tempo 90` | Top level only, outside every block. See [Settings](/language/settings). |
| `with` | `with key E { ... }` | Anywhere a statement or a line goes: settings for its block only. See [with](/language/settings#with). |
| Declaration | `steps fill = x-x-` | Anywhere. See [Names](#names). |
| Line | `kick: x--x---` | In a block, or after `play`. See [Types](#types). |
| Group | `(intro verse verse)` | In a block, or after `play`. What plays in order goes in brackets. See [Groups](/language/patterns#groups). |
| `on bar`, `every` | `lift on bar 4` | In a block, or after `play`. See [bar](/language/patterns#bar) and [every](/language/patterns#every). |
| Value | `chords 1 4 5`, `melody` | Top level only. It is evaluated, and shown when it is the cell's last statement. See [print without playing](/language/play#print-without-playing). |
| `play` | `play groove` | Top level only, which includes the top of a `with` there. See [play](/language/play). |

## Types

Every value has one of five types. A line is a kit piece or an instrument, a colon and a value, and the name before the colon decides the value's type. So the drums and the pitched instruments never take each other's values: a `steps` name on `bass` is an error, and so is a `notes` name on `kick`. A `pattern` holds lines of both.

| Type | A value is | Literal | Used | See |
| --- | --- | --- | --- | --- |
| `steps` | Hits for one kit piece, as step words. | `x--x---`, `8*- x` | After a kit piece's colon. | [Steps](/drums/steps) |
| `notes` | Notes for one instrument, one at a time, by name or by degree of the key. | `E---F# E-E--`, `1---3---5---` | After `notes` on an instrument's line. | [Notes](/pitched/notes) |
| `chords` | Bars of chords. | `Am F\|C G` | After `chords` on an instrument's line. | [Chords](/pitched/chords) |
| `pattern` | Lines that play together and repeat. | `pattern { kick: x--- }` | After `play`, on a line of its own, or in a group. | [Patterns](/language/patterns) |
| `block` | Lines that play together once. | `block { crash: x }` | After `play`, on a line of its own, or in a group. | [Blocks](/language/patterns#groups) |

## Names

A declaration binds a name to a value: `<type> <name> = <value>`. The type is required. A name is accepted only where its type is, and only below its declaration.

<Cell>

```composer-nb
steps backbeat = 4*- x 3*-
notes walk = A1 7*- F1 7*- | C2 7*- G1 7*-
chords verse = Am F|C G

pattern groove = {
  snare: backbeat,
  hat: x-,
  bass: notes walk,
  piano: chords verse,
}

play groove
```

</Cell>

A name of any type starts with a lowercase letter, then holds letters and digits, with a capital for each new word: `riff`, `partA`, `countIn`, `at100`. It is at least two characters long and not a Roman numeral, so it never reads as a step or a chord. Two names that differ only in their capitals are an error, including when one comes from a cell above. A name is defined once in a cell: defining it again is an error, inside a block too when it's defined outside it. A cell can define again a name from a cell above.

## Blocks

A block is statements in braces. What's in front of the braces decides what they evaluate to. Braces that are a value say their type, so a bare `{ ... }` after `play`, on a line of its own or in a group is an error.

| Block | Evaluates to |
| --- | --- |
| After `pattern`, `pattern <name> =`, `every` | A `pattern`. |
| After `block` or `block <name> =` | A `block`. |
| After `with` and its settings | At the top of a cell, the statements in it. Anywhere else, a `pattern`, played with the settings. |
| After a kit piece's colon | One `steps` value, from [layers](/drums/steps#layers). |
| After an instrument's colon | [Layers](/pitched/notes#layers) of `notes` and `chords` that sound together. |

The statements in a block start together. Separate them with `,`, whether the block is on one line or many. A trailing comma before `}` is allowed. Newlines inside braces are layout, so an entry may wrap across lines. What plays in order goes in brackets: a [group](/language/patterns#groups) holds names, blocks, groups and lines, one after another, separated by spaces or new lines. Braces hold what plays together and brackets what plays in order, so a newline never decides between them.

| Written | Plays |
| --- | --- |
| `pattern { ... }` on a line of its own | Together with the other lines. |
| `(pattern { ... } block { ... })` | One after another. |
| `intro verse`, `pattern { ... } outro` | An error: what plays in order goes in brackets. |

<Cell>

```composer-nb
play block {
  (pattern { kick: x---, } pattern { snare: x---, }),
  pattern { hat: x-, },
}
```

</Cell>

The kick plays first and the snare after it, with the hats under both.

A block holds one line per kit piece or instrument. To layer one, give its line a block.

Where a line is decides whether it repeats. In a pattern, every line repeats until the pattern ends; write each kit or note line's repeating figure once. In a block, or on its own after `play`, a line plays once and may use finite repeats such as `8*x-` or `2*(1--- 3---)`. Named `steps` and `notes` values can also contain finite repeats. Chord charts write repeated bars once: `chords Am F|Am F` is `chords Am F`.

`print(...)` inspects finite musical values without playing them. It shows each value with what it resolves to in parentheses: `1(C3)`, `6m(Am(A3 C4 E4))`. See [print without playing](/language/play#print-without-playing).

## Lengths

A length in bars sets how long a pattern, block or group plays: `4 bars groove`. Units are always plural, even after 1: `1 bars`. `every 3/4 beats` sets the step duration. Kit and note lines use step [repeats](/drums/steps#repeats), such as `8*-` or [`1 7*-`](/pitched/notes#repeats-and-holds). A final `...` fills the rest of the containing block: `...x-` repeats a drum word, `...G1` holds a note, and `..._` leaves notes silent.

| Unit | Lasts |
| --- | --- |
| Steps counted by `*` | A sixteenth note each, unless [`every`](/language/patterns#every) changes it. |
| `beats` in `every` | A quarter note, in every time signature. |
| `bars` for pattern, block or group lengths | One bar of the current [`time`](/language/settings#time). |

Settings and lengths can use arithmetic: `set tempo 60*2`, `every 1/3 beats`. Repeat counts are literal whole numbers of at least two.

## Scope

- A `set` applies from its line to the end of the cell. It goes only at the top of a cell; inside a block, settings go on a `with`.
- A `with`'s settings apply to its block only, and what was set before comes back at its `}`.
- A declaration applies from its line to the end of the cell, or of the block it is in, including a `with`'s.
- A pattern is evaluated where it is played, with the settings in effect there, and with the names written above it: a later cell that defines a name again doesn't change what an earlier pattern plays.
- The settings set at the top and the names declared there carry into other cells; a `with`'s never do. In the playground, a cell starts from the cells above it. In Jupyter, it starts from the cell named by [`after`](/jupyter#cells-that-continue).
