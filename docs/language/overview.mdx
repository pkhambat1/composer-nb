## Cells

A cell is a program. The interpreter evaluates its statements top to bottom, one per line, and each `play` renders one output. Nothing else makes sound. `//` starts a comment, and a line that starts with `|` continues the line above it, at a bar line.

| Statement | Example | Allowed |
| --- | --- | --- |
| Setting | `set tempo 90` | Anywhere. See [Settings](/language/settings). |
| Declaration | `steps fill = x-x-` | Anywhere. See [Types](#types). |
| Line | `kick: x--x---` | In a block, or after `play`. |
| Group | `(intro verse verse)` | In a block, or after `play`. What plays in order goes in brackets. See [Groups](/language/patterns#groups). |
| `bar`, `every` | `bar 4 { ... }` | In a block, or after `play`. See [bar](/language/patterns#bar) and [Step length](/language/steps#step-length). |
| `play` | `play groove` | Top level only. See [play](/language/play). |

## Types

Every value has one of four types.

| Type | A value is | Literal | Used |
| --- | --- | --- | --- |
| `steps` | Hits for one kit piece, one character per step. | `x--x---` | After a kit piece's colon. See [Steps](/language/steps). |
| `notes` | Notes for one instrument, one at a time, by name or by degree of the key. | `E---F# E-E--`, `1---b3---5---` | After an instrument's colon. See [Notes](/language/notes). |
| `chords` | Bars of chords. | `Am F\|C G` | After `chords` on an instrument's line. See [Chords](/language/chords). |
| `pattern` | Lines that play together and repeat. | `{ kick: x--- }` | After `play`, or in a group. See [Patterns](/language/patterns). |

A declaration binds a name to a value: `<type> <name> = <value>`. The type is required. A name is accepted only where its type is, and only below its declaration.

<Cell>

```composer-nb
steps backbeat = 2 4
notes walk = 2 beats A1, 2 beats F1 | 2 beats C2, 2 beats G1
chords verse = Am F|C G

pattern groove = {
  snare: backbeat
  hat: x-
  bass: walk
  piano: chords verse
}

play groove
```

</Cell>

A name of any type starts with a lowercase letter, then holds letters and digits, with a capital for each new word: `riff`, `partA`, `countIn`, `at100`. It is at least two characters long and not a Roman numeral, so it never reads as a step or a chord. Two names that differ only in their capitals are an error, including when one comes from a cell above.

## Blocks

A block is statements in braces, and it evaluates to a value. Where the block is decides its type.

| Block | Evaluates to |
| --- | --- |
| After `pattern <name> =`, `play`, `bar` or `every` | A `pattern`. |
| After a kit piece's colon | One `steps` value, from [layers](/language/steps#layers). |
| After an instrument's colon | [Layers](/language/notes#layers) of `notes` and `chords` that sound together. |

The statements in a block start together, one per line. What plays in order goes in brackets: a [group](/language/patterns#groups) holds names, blocks, groups and lines, one after another, separated by spaces or new lines. Braces hold what plays together and brackets what plays in order, so a newline never decides between them.

| Written | Plays |
| --- | --- |
| `{ ... }` on a line of its own | Together with the other lines. |
| `({ ... } { ... })` | One after another. |
| `intro verse`, `{ ... } outro` | An error: what plays in order goes in brackets. |

<Cell>

```composer-nb
play {
  ({ kick: x--- } { snare: x--- })
  { hat: x- }
}
```

</Cell>

The kick plays first and the snare after it, with the hats under both.

A block holds one line per kit piece or instrument. To layer one, give its line a block. On a kit piece's line, or a layer, a block is the whole value, so nothing goes beside it: `hat: x--- { ... }` is an error. To put steps in a row with a block, name it: `steps fig = { ... }` and `hat: x--- fig`.

Where a line is decides whether it repeats. In a pattern, every line repeats until the pattern ends. Directly in a `play`, a line plays once. A `steps` value is not a loop: `x--x---` is seven steps, and the pattern around it does the repeating. So a `steps`, `notes` or `chords` value written as the same figure more than once is an error: `hat: x-x- x-x-` is `hat: x-`, and `chords Am F|Am F` is `chords Am F`.

## Lengths

A length is a number and a unit, written in front of what it measures: `4 bars groove`, `2 beats rest`, `3 beats C2`, `every 3 steps`. Units are always plural, even after 1: `1 bars`. On a line, `...` is the length that is left of the block: `...rest`, `...x-`, `...G1`. On a kit piece's line a length repeats a figure, because a hit has no duration; on an instrument's line it holds one note, because a note has one.

| Unit | Lasts |
| --- | --- |
| `steps` | One step: a sixteenth note, unless [`every`](/language/steps#step-length) changes it. |
| `beats` | A quarter note, in every time signature. |
| `bars` | One bar of the current [`time`](/language/settings#time). |

Any number can be arithmetic: `set tempo 60*2`, `every 1/3 beats`.

## Scope

- A setting or declaration applies from its line to the end of the cell, or of the block it is in. A block's lines play together, so its `time`, `tempo` and `swing` go above all of them.
- A pattern is evaluated where it is played, with the settings in effect there.
- The settings and names at the end of a cell carry into other cells. In the playground, a cell starts from the cells above it. In Jupyter, it starts from the cell named by [`after`](/jupyter#cells-that-continue).
