title: "Cells and statements"
description: "How source text is divided into cells, statements, entries and tokens."
---

A notebook is a sequence of cells. A cell is a sequence of statements, evaluated from top to bottom. A statement changes a setting, declares a name, plays music or displays a value. Each kind of statement has its own page; this page defines what they share.

## Cells

```text Syntax
cell      ::= (statement NEWLINE)*
statement ::= set_stmt | with_stmt | declaration | play_stmt | print_stmt | value_expr
```

| Statement | Effect | Defined in |
| --- | --- | --- |
| `set_stmt` | Changes one setting from that line onward. | [set](/language/scope#set) |
| `with_stmt` | Runs statements under local settings. | [with](/language/scope#with) |
| `declaration` | Binds a name to a value. Produces no sound. | [Declarations](/language/values#declarations) |
| `play_stmt` | Renders a part as one musical output. | [play](/language/play) |
| `print_stmt` | Displays values. Produces no sound. | [print](/functions/print) |
| `value_expr` | Displays its value when it is the last statement of the cell. | [Last expression](/functions/print#last-expression) |

A cell with no `play` produces no audio. Each `play` produces one output, and a cell's outputs play in statement order. Settings and names left at the top level of a cell are inherited by the cells after it; see [Cells and inheritance](/language/scope#cells-and-inheritance).

A cell that contains any error produces no output at all: nothing plays and nothing prints. Every error reports its line. Declarations are checked even if nothing uses them.

## Lexical structure

| Token | Meaning |
| --- | --- |
| Newline | Ends a statement at the top level. Inside `{ }` and inside the parentheses of `print` it is layout only. Inside a [group](/language/patterns#groups) it ends an instrument line. |
| `,` | Separates the entries of a `{ }` body, the settings of a `with`, and the arguments of a call, and the properties of a `voice` shift object. Required between entries even when they are on separate lines. One trailing comma before `}` is allowed. |
| `{ }` | A body: entries that belong together. What an entry may be depends on what the braces belong to. In the second argument of `voice`, braces hold a chord-tone shift object. |
| `( )` | A group of parts played in order; also arithmetic grouping, a repeat group and call arguments. |
| `:` | Joins a kit piece or instrument to what it plays. |
| `=` | Joins a declared name to its value. |
| `\\|` | A bar line. A line that starts with `\\|` continues the statement on the line above. |
| `//` | A comment, to the end of the line. |

Blank lines and indentation have no meaning, with one exception: a blank line ends a statement, so a `|` continuation line must follow its statement directly. Comment lines may sit between a statement and its continuation. Semicolons are not separators.

Keywords are lowercase. The language has no string literals, no conditionals, no loops and no user-defined functions.

## Where each statement is allowed

| Statement | Cell top level | Inside a top-level `with` | Inside a body or group |
| --- | --- | --- | --- |
| `set` | Yes | No | No |
| `with` | Yes | Yes | Yes, as a part |
| Declaration | Yes | Yes | Yes |
| `play` | Yes | Yes | No |
| `print` | Yes | Yes | No |
| Value expression | Yes; displayed only when last | Checked, never displayed | No |
| Instrument line | No | No | Yes, and directly after `play` |

## Errors

```composer-nb Invalid
play pattern { kick: x---; snare: --x- }
```

```text Error
Use commas between entries in braces instead of semicolons; a trailing comma is allowed
```

```composer-nb Invalid
kick: x---
```

```text Error
An instrument's line goes inside braces: in a pattern, or play block { kick: x--- }
```

```composer-nb Example
play({ kick: x--- })
```

Bare braces default to a block. Use `pattern({ ... })` for repetition.
