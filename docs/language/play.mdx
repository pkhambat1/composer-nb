import { Cell } from "/snippets/cell.jsx"

`play` evaluates what follows it and renders one output. It is the only statement that makes sound, and it goes at the top level of a cell.

```text
play <name, group or line> [for <number> bars]
play block { <statements> } [for <number> bars]
play pattern { <lines> } [for <number> bars]
```

<Cell>

```composer-nb
pattern groove = {
  kick: x---,
  snare: ----x---,
}

play groove
play piano: chords Am F for 2 bars
play block {
  crash: x 15*-,
  groove,
} for 4 bars
```

</Cell>

This cell renders three outputs.

## What repeats

A play is a timeline, and its statements start together. The braces after `play` say their type, as any others do, so a bare `play { ... }` is an error. `play block { ... }` plays its statements as this table says.

| In a play | Plays |
| --- | --- |
| A line | Once. |
| A block | Once, with silence after it if the play runs longer. |
| A pattern, or a group in brackets | Repeated until the play ends. A group plays what's in it in order. |
| `every` | Repeated until the play ends. |
| `bar <n>` | In bar `n`. |

`play pattern { ... }` repeats every line in it, as any pattern does.

<Cell>

```composer-nb
play block {
  kick: x---,
  snare: ---- x---,
} for 2 bars

play pattern {
  kick: x---,
  snare: ---- x---,
} for 2 bars
```

</Cell>

The first output plays each line once, then silence. The second repeats both lines for two bars.

## Duration

Write `play groove for 2 bars` to set the whole output’s duration. The duration follows the music; `play 2 bars groove` is rejected.

Without a duration, a play lasts as long as its longest statement, and what repeats must fit that a whole number of times. With a length, it lasts exactly that long: whatever is repeating stops at the end, and silence fills any time left over. A play can't run past 10 minutes.

After braces, the length is theirs: a pattern in `play block { ... } for 4 bars` repeats to fill all four bars. A name keeps the length it was declared with, so `play accent for 4 bars` plays the block `accent` once, then silence.

## Output

- A header with the time, tempo, key, number of bars and the instruments that play.
- Audio, with a waveform to follow and seek.
- A grid of every hit and note, bar by bar. The playground can draw it as sheet music instead: the kit on a percussion staff with hands up and feet down, each instrument on a staff of its own (a guitar with its tab) in the signature of the [`key`](/pitched/key), and the sheet prints.
- The chords played. The playground draws a diagram for each.

## Print without playing

`print(...)` evaluates musical values and displays them as text with resolved musical details. It omits rests, sustain marks and bar lines; repeated notes, chords and drum hits remain in order. Silence alone evaluates to `[]`. It creates no player, audio, MIDI events, or elapsed musical time. It can run alongside `play` statements, and inside a top-level `with` block.

<Cell>

```composer-nb
print(1, 2, 3)
print(fifth(1 3 5 7))

chords harmony = 1 3|4 5
print(harmony, fifth(harmony))

with key D, mode minor {
  print(1, 2, 3),
}
```

</Cell>

Each type prints as one line: the type, then each value with what it resolves to in parentheses.

```text
notes 1(C3), 2(D3), 3(E3)
notes 5(G3) 7(B3) 9(D4) 11(F4)
chords 1(C(C3 E3 G3)) 3(Em(E3 G3 B3)) 4(F(F3 A3 C4)) 5(G(G3 B3 D4))
```

A note is followed by its pitch. A chord written as a degree is followed by its name, and the name by its tones. Interval functions preserve that degree identity: with `chords tonic = 1`, `print(fifth(tonic))` shows `5(G(G3 B3 D4))` in C major. A chord written by name is followed by its tones. A chord over a bass ends with the bass after a slash: `1/3(C/E(C3 E3 G3/E2))`. Arguments of one type share a line, separated by commas, and a change of type starts the next line. Under the scoped D minor setting, the same `1, 2, 3` prints `1(D3), 2(E3), 3(F3)`.

A value on a line of its own is evaluated too, and the cell shows it when it is the cell's last statement, as a notebook shows a cell's last expression. Anywhere else it is checked and shows nothing; `print(...)` shows a value from any line.

<Cell>

```composer-nb
chords harmony = 1 3|4 5
fifth(harmony)
```

</Cell>

Such a value says its type, as it does after an instrument's colon, or is a name or an interval function of names: `chords 1/3 C/E`, `notes fifth(1 3 5 7)`, `steps 2*(x- ^-)`, `harmony`, `fifth(harmony)`. A literal without its type, such as `1 2 3`, is an error, because it could be notes or chords.

Each comma at `print`'s own level starts another argument. A comma inside `fifth(1, 2)` still belongs to the interval function. Named values keep their declared type. Bare degrees and letters are inspected as notes; use a `chords` prefix to inspect them as chords: `print(chords 1 2 3)`. A chord's details include its name and tones. `print(steps 2*(x- ^-))` inspects finite drum steps.

Holds, rests, bar lines and `*` repeats stay visible. When `transpose` is set, the parentheses hold the sounding pitches: with `set transpose 2`, `1` prints as `1(D3)` and the chord `1` as `1(D(D3 F#3 A3))`. A final `...` needs a containing musical block and cannot be printed as a finite value. `print` is an output statement; it cannot be nested inside a musical function, pattern or play block.
