---
title: "Scope"
description: "Where settings and names are in effect: `set`, `with`, braces and cells."
---

Two things are scoped: settings and names. The settings in effect at a point are its environment. `set` changes the environment for the rest of the cell and for later cells. `with` changes it for one pair of braces. Neither is tied to a particular type: a `with` may wrap statements at the top level or any part inside music.

The settings themselves, with their values, defaults and ranges, are listed in [Settings](/language/settings).

## The environment

Evaluation starts in the default environment: `time 4 over 4`, `tempo 120`, `swing off`, `key C`, `mode major`, `octave 3`, `transpose 0`, `kit rock`, `guitar.electric clean`.

Music reads its settings where it plays, not where it was declared. A named `notes` value declared under `key C` and played under `key D` plays in D.

## set

```text Syntax
set_stmt ::= "set" setting
```

| Operand | Type | May be |
| --- | --- | --- |
| `setting` | `setting` | Any one setting and its value; see [Settings index](/language/settings#settings-index). |

Changes one setting from this statement onward: statements above it are unaffected, and the value in effect at the end of the cell is inherited by later cells. A setting may be set more than once.

`set` is a top-level statement only. It may come between other statements, but not inside any braces.

```composer-nb Example
play piano: notes 1---
set key D
play piano: notes 1---
```

The first `play` sounds C3 and the second D3.

```composer-nb Invalid
with key D { set tempo 90 }
```

```text Error
Inside a block, settings go on a with: with tempo 90 { ... }
```

## with

```text Syntax
with_stmt  ::= "with" settings "{" statement ("," statement)* [","] "}"
with_scope ::= "with" settings body
settings   ::= setting ("," setting)*
```

| Operand | Type | May be |
| --- | --- | --- |
| `settings` | `setting`, one or more | Any settings, separated by commas, each at most once. No `set` keyword and no trailing comma. |
| `statement` | statement | A declaration, `play`, `print`, value expression or nested `with`. Not `set`. |
| `body` | body | `{ entry, ... }`, as in a pattern; see [Bodies](/language/patterns#bodies). |

Applies its settings to everything inside its braces, then restores the environment. A nested `with` starts from the outer one's settings. Names declared inside stay inside.

`with` has two forms, chosen by where it stands:

| Where | Form | Braces hold | Result |
| --- | --- | --- | --- |
| Cell top level, or inside another top-level `with` | `with_stmt` | Statements, separated by commas. | The statements run under the local settings. |
| Wherever a part may stand: after `play`, in a body, in a group, as the value of a `pattern` or `block` declaration | `with_scope` | Entries, separated by commas. | A part. Its entries sound together and its lines repeat, as in a pattern. |

```composer-nb Example
with key D, octave 2 {
  print(chords 4),
  play bass: notes 1---5---,
}
```

```text Output
chords 4(G(G2 B2 D3))
```

```composer-nb Example
play pattern {
  kick: x---,
  with octave 2 { bass: notes 1---5--- },
  piano: chords C G,
}
```

Which settings a `with_scope` may change depends on what sounds beside it. Parts that sound together share one clock, so they must share `time`, `tempo` and `swing`. To change one of those, put the `with` around the whole `play`, or on a part of a group, where parts play one after another. All other settings may differ between parts that sound together.

```composer-nb Example
play (
  with tempo 90 { pattern { kick: x--- } }
  with tempo 140 { pattern { kick: x--- } }
)
```

```composer-nb Invalid
play pattern { hat: x-, with tempo 90 { kick: x--- } }
```

```text Error
The lines of a play or a pattern play together, so they share one tempo. Put the with around the whole play, with tempo 90 { play ... }, or on a part that plays in order: ( with tempo 90 { ... } )
```

A `with` goes around an instrument's line, never among its layers, and it cannot be an argument of a function.

```composer-nb Invalid
with key D, key E { print(1) }
```

```text Error
key is in this with twice. A with sets each setting once
```

## Names in scope

| Declared | Visible |
| --- | --- |
| At the cell top level | From its line to the end of the cell, and in later cells. |
| Inside braces | From its entry to the closing brace, including nested braces. Not outside. |

A name must be declared above its first use. A declaration cannot reuse a name that is visible at that point, including one from enclosing braces. Two sets of braces that do not enclose one another may each declare the same name.

```composer-nb Example
play pattern { notes riff = 1---, piano: notes riff }
play pattern { notes riff = 5---, piano: notes riff }
```

```composer-nb Invalid
notes riff = 1---
play pattern { notes riff = 5---, piano: notes riff }
```

```text Error
riff is already defined on line 1. A name is defined once, so pick another name
```

## What a name captures

| Name of type | Resolves the names it uses | Reads settings |
| --- | --- | --- |
| `steps`, `notes`, `chords` | When declared: the referenced values are copied in. | Where it is played or printed. |
| `pattern`, `block` | When declared: it keeps the definitions visible at that point. | Where it is played. |

Declaring a name again in a later cell does not change values that already used the old definition.

## Cells and inheritance

A cell inherits the environment and the top-level names left by the cells above it. Inherited names may be declared again, with any type. Settings and names from inside a `with` or a body are never inherited.
